02 · Energy-first inference

MilliJoule

An LLM inference engine that treats energy as the main metric: as few joules per output token as possible on modern GPUs.

The idea

Inference engines are tuned for speed and cost per hour. As AI use grows, the number that will matter more is energy: how many joules it takes to produce each token.

MilliJoule starts from that number. Every design choice, from how requests are batched to which GPU kernels run, is judged by joules per output token at a fixed latency limit, measured on the GPU itself.

Architecture

Where the
joules go

Energy is spent at every stage of serving a request, so the engine is built and measured as one system.

01

Scheduler

Continuous batching keeps the GPU busy, with prompt processing mixed into decode steps.

02

Memory

A paged KV cache and shared prefix cache avoid recomputing work that has been done before.

03

Kernels

GPU kernels and execution graphs chosen for energy, starting with mixture-of-experts models.

04

Hardware

Built for Blackwell-class GPUs and newer, using what that hardware offers rather than the lowest common denominator.

05

Meter

The GPU's own energy counter is read for every benchmark, and each number says what was measured.

Method

How we
measure

  • M1
    Measure on the hardwareEnergy comes from the GPU board's own counter, not from estimates. Wall power is quoted only when we can measure it.
  • M2
    Respect the noiseThe counter is accurate to roughly ±5%, so a change only counts if it moves joules per token by more than that and a repeat run agrees.
  • M3
    Never quote a number aloneEvery published figure comes with its latency limit, number format, GPU and measurement boundary, so it can't be compared unfairly.
  • M4
    Count idle powerPower drawn with the model loaded and no traffic is recorded, because a real server spends time waiting too.
